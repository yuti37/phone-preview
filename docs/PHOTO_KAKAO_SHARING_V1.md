# 照片與 KakaoTalk 分享 V1

## 本機可用功能

照片檢視器的分享面板只允許下列三組配對，每組單次傳送。必須確認照片成功解碼、故事時間不早於照片時間、接收者沒有衝突中的待回覆事件，再由玩家明確確認。取消不寫入資料。

| 互動事件 ID | 照片 ID | 接收者 | 既有照片故事時間 |
| --- | --- | --- | --- |
| photo-share-v1:meal-minhyuk | photo-9376 | 玟赫 | 2026/10/21 19:58 |
| photo-share-v1:work-manager | photo-9370 | 經紀人 | 2026/10/23 15:05 |
| photo-share-v1:restaurant-shownu | photo-9333 | 賢佑 | 2026/10/21 20:41 |

這些時間是現有虛構故事設定，不是照片真實拍攝日期。傳送時間取既有故事時間與該聊天室最新有效訊息的較晚值，再加一秒；不讀取裝置日期來推進劇情。所有照片仍沿用原始資產與相簿分類。

## 已核准並啟用的回覆

以下為使用者核准的虛構文案，不引用私人聊天語料。三組 `replyApproved` 均為 true，只在玩家新確認分享時建立對應回覆事件。舊存檔沒有分享事件，或舊分享未配置回覆時，不會追溯補發。

### 玟赫：舊餐點照片

- 韓文：이거 보니까 또 배고프네 ㅋㅋ 맛있었어?
- 繁中：看到這個又餓了ㅋㅋ 好吃嗎？
- 確認分享後延遲 3 秒送達；故事時間為分享後一分鐘。不假設這是當天剛吃的餐點。

### 經紀人：工作側拍

- 韓文：사진 확인했어요. 기록용으로 보관해 둘게요.
- 繁中：照片確認了，我會留作紀錄。
- 確認分享後延遲 3 秒送達；不新增工作安排、場次或任務。

### 賢佑：共同餐廳經歷

- 韓文：그날 잘 먹었지 ㅋㅋ 사진 보니까 생각나네.
- 繁中：那天吃得挺好的ㅋㅋ 看到照片就想起來了。
- 確認分享後延遲 3 秒送達。只有原有飲酒互動及主線待回覆結束後才可分享；不推進感情或跨 App 劇情。

## 資料及恢復

- 圖片訊息沿用原有 KakaoTalk schema，加入 `type: photo`、`photoId`、`sourceEventId`。舊文字訊息不變。
- 在既有事件儲存庫加入獨立的 `photoSharesV1` 版本化區塊，沒有新增儲存鍵。紀錄與訊息事件以同一次儲存寫入；失敗則還原記憶體，不顯示成功。
- 單次配對由穩定事件、訊息及紀錄 ID 三重去重。舊存檔缺欄位視為空；損壞或未知版本不覆寫。
- 已送照片透過既有完成事件重播機制重建，保留原本訊息去重、排序與已讀機制，不寫入主線對話事實。
- 已預留經核准回覆的快照及排程支援，共用既有事件資格檢查。待送回覆不占用主線 pendingReply；衝突時安全暫緩並重新驗證。
- 三組正式回覆各自建立單次事件，故事時間為分享後一分鐘；重載使用已保存的回覆快照。自動化測試同時涵蓋正式文案及隔離的人工快照資料。
- 原有重新開始機制會一併移除事件庫內分享狀態，不碰其他儲存鍵。

## 開發測試

- 自動化：`node --test tests/*.test.js`（Windows 可先列出測試檔再傳入）。
- 選用瀏覽器測試：`node tests/photo-kakao-sharing.browser.cjs`，開發環境需提供 Playwright，必要時由 `CHROME_EXECUTABLE` 指定 Chromium。測試只建立臨時無持久化的瀏覽器 context 與本機靜態伺服器。
- 瀏覽器測試檢查 320、390、430px；不等同真實 iPhone Safari 驗收。
